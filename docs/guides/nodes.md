# 节点详解

工作流由节点组合而成。当前版本内置 **36 类**可执行节点，节点面板按 **AI / AI 工具 / 数据 / 控制流 / 工具** 五组组织。下面按分组给出每个节点的名称与作用。

## 节点总览

### AI（3）

| 节点 | 作用 |
| --- | --- |
| AI 对话 | 智能体的大脑，调用已接入的模型生成回答，支持多轮推理与工具调用 |
| 上下文压缩 | 压缩或摘要历史对话、管理便签分区，避免长会话超出承载范围 |
| AI 便签提取 | 用模型从输入中抽取结构化的关键事实，形成便签 |

### AI 工具（12）

| 节点 | 作用 |
| --- | --- |
| 创建文件 | 在指定位置新建文件并写入内容 |
| 读取文件 | 读取文件内容，可同时查看行号与原始文本 |
| 目录列表 | 列出目录结构，可设置展开深度 |
| 文件搜索 | 按名称或路径模式查找文件 |
| 内容搜索 | 在文件内容中查找关键字 |
| 数据修补 | 按给定的修改内容更新文件 |
| 文件上传 | 上传本地文件并返回文件信息 |
| 文件下载 | 把文件下载到指定位置 |
| 终端执行 | 在流程中执行预设指令并查看输出 |
| 技能列表 | 列出当前可用的技能 |
| 技能下载 | 把技能下载到本地工作目录 |
| 技能执行 | 执行指定技能或技能中的操作 |

### 数据（5）

| 节点 | 作用 |
| --- | --- |
| 数据库检索 | 连接已配置的数据源执行查询 |
| 数据库插入 | 向业务数据源写入数据 |
| 缓存查询 | 读取已缓存的中间结果 |
| 缓存写入 | 把结果写入缓存，可设置有效期 |
| 知识检索 | 从知识库召回相关资料 |

### 控制流（6）

| 节点 | 作用 |
| --- | --- |
| 开始节点 | 流程起点，接收用户问题、上下文、图片、视频等输入 |
| 条件判断 | 依据变量或模型输出走不同分支 |
| 循环 | 对列表或重复任务逐项处理，携带循环子画布 |
| 循环开始 | 循环子画布的起始节点 |
| 循环跳过 | 满足条件时跳过本次迭代 |
| 跳出循环 | 满足条件时提前结束循环 |

### 工具（10）

| 节点 | 作用 |
| --- | --- |
| JavaScript 执行 | 通过脚本处理数据或生成结果 |
| 参数提取 | 从文本或输入中提取结构化参数 |
| 变量赋值 | 保存或更新流程变量 |
| 数据响应 | 把结果作为最终响应返回 |
| 推送上下文 | 把内容追加进上下文供后续节点使用 |
| 上下文查询 | 读取历史上下文、摘要与便签 |
| 上下文写入 | 把摘要与便签保存下来 |
| 当前用户 | 取当前登录用户的信息与角色 |
| 调用工具 | 调用已配置的工具或工具流程 |
| 审批 | 在关键步骤暂停，等待人工确认后继续 |

:::note 画布差异
「静态文件」目前仅作为处理器 / 工具画布的模板节点出现，不计入上述 36 类。节点可用性随画布类型（应用 / 处理器 / 工具及其循环子画布）变化。
:::

## 两条容易混淆的链路

- **知识库检索**：人把文档或 PDF / Word 文件导入知识库，系统做全文检索召回，通过「知识检索」节点把片段喂给模型。
- **上下文管理**：模型在会话中自动提取便签、压缩历史并保存摘要，再由「上下文压缩 / 查询 / 写入 / 推送上下文」节点消费。属于会话记忆，与知识库是两条独立链路。

详见 [知识库与文档](/guides/notes) 与 [工作流引擎](/guides/workflow)。

## 组合建议

一个典型的业务智能体往往是这些节点的组合：

1. 用 **开始节点** 接收问题。
2. 用 **知识检索** 召回私有资料。
3. 用 **AI 对话** 理解意图。
4. 用 **条件判断** 决定是否需要查询业务库：需要时走 **数据库检索** 再交给 **AI 对话** 回答，否则走 **调用工具** 对接外部系统。
5. 敏感操作前插入 **审批** 由人工确认。
6. 最后用 **数据响应** 返回结果。

需要批量处理时，把中间部分放进「循环」节点的循环子画布，用「循环跳过」「跳出循环」控制迭代。

各节点的参数配置方式，参见 [功能手册总览](/manual/overview) 中的应用画布说明。
